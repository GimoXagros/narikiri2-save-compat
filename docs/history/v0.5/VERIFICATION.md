검증 기간: 2026-09-03~04. Python 3.12.13 / Windows 로컬 환경.

## 새 복구 도구에서 확인한 결과

- 정확한 최초 K_FFR 및 일본어 입력으로 새 출력 두 개 생성.
- 결과 두 개 모두 12,582,912바이트, SHA-256 `9c7a8ae87c303a16c71bd164e7409a5aaabf01bd3246fa9e700931eed6179d4f`.
- 기존 저장·로드 검증을 마친 v0.5 ROM과 전체 바이트 비교 일치.
- 실제 변경 위치가 지정한 6개 구간의 79바이트와 정확히 일치. 모든 나머지 바이트 보존.
- 두 입력의 SHA-256 불변. 텍스트·폰트·포인터·헤더·ROM 크기 불변.
- 합성 데이터 자동 검사 22개 통과, 생략 0. 잘못된 입력/출력 해시, 범위 밖 변경, 쓰기 중복, 길이 오류, 기존 파일과 입력 경로 보호, 뒤늦게 생성된 파일 덮어쓰기 차단, 세이브 미변경 등을 검사.

기계 판독 기록: [verification/v0.5.json](verification/v0.5.json).

실제 입력과 이전 검증본을 보유한 개발자는 다음으로 전체 동일성을 다시 검증할 수 있습니다. --work-dir는 새 로컬 폴더여야 합니다. 생성되는 ROM과 로컬 경로는 저장소에 올리지 마십시오.

```powershell
python tools/verify_local.py --korean "최초_K_FFR.gba" --japanese "일본어_원본.gba" --baseline "검증된_v0.5.gba" --work-dir output/local-check
```

## 기존 런타임 근거의 적용 범위

이번 공개 도구는 ROM의 저장 코드 설계를 새로 바꾸지 않습니다. 위 전체 바이트 동일성에 의해서만 다음 기존 관찰을 연결합니다. 이번에 새 에뮬레이터/실기 검사를 수행했다는 주장은 하지 않습니다.

기존 동일 ROM의 mGBA libretro 0.11-219-e31759b / HLE BIOS 검사:

- 세이브 없는 새 게임 → 최초 게임 내 저장 → 프로세스 종료·재실행·로드.
- 추가 진행과 아이템 구매 → 두 번째 저장 → 프로세스 종료·재실행·로드.
- 게임 시간 19분, 소지금 192와 구매 아이템 수량 1 유지 확인.
- 제공된 유효한 VBA-M 32 KiB 세이브 하나는 별도 8 KiB 변환 후 로드·재저장·재실행·로드 확인. 새 도구에는 이 변환 기능이나 샘플을 포함하지 않음.

기존 core SHA-256: `0d3177c927d791fef897f735d88db3646f7932d02054af108619c6df4e1597f1`.

GBARunner3에서는 사용자가 동일 Candidate A ROM의 저장·로드 성공을 보고했습니다. 정확한 기기·GBARunner3 실행 파일 버전과 두 번째 저장·재로드 주기는 확인되지 않았습니다. 이 관찰을 모든 실기에 대한 보증으로 확대하지 않습니다.

## 배포 및 권리 검토의 한계

새 저장소와 ZIP은 명시적 목록의 소스·문서·합성 테스트·검증 메타데이터만 포함합니다. 이 검사는 제3자 데이터와 과거 이력을 실수로 배포하는 것을 막기 위한 것이며, 모든 관할의 법적 적합성을 판정하는 검사는 아닙니다.

전체 게임 플레이, 모든 메뉴·도감·전투, 모든 저장장치와 실행기 버전은 전수검증하지 않았습니다. 기존 게임의 잠재 버그와 번역 문제는 수정 범위 밖입니다.
